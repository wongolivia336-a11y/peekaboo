# SH03「躲藏的幸福」2.5D delivery

本交付把 `IMG-001` 原画作为唯一视觉源，做成一个 10 秒、24 fps、可逐帧定位的 PixiJS 2.5D 镜头。画面不依赖重绘或生成式替代图；所有移动层都来自原图的 source-coordinate crop，并保留原画 RGB 与笔触。

- Source: `assets/images/IMG-001-tree-hide-v01.png`
- Size: `1448 × 1086`
- SHA-256: `5bdda3d0d314a20af09df6ef1480ccc888a002ee5a3054228e88857c2c9730f4`

- Source pixels are copied unchanged. `scripts/build-assets.py` fails closed if the hash or dimensions change.

## Runtime choice

采用 PixiJS 8.22.0 + TypeScript + Vite。原因是本镜头的核心价值是原画的纸面纹理、局部遮罩与低幅度二维形变；当前不需要真正的三维摄像机、法线、灯光或深度材质，所以没有引入 Three.js runtime。

`img2threejs` 已按官方命令尝试：

```text
npx --yes img2threejs@latest install
npx --yes img2threejs@latest doctor
```

官方 CLI 当前明确标注 Windows 尚未支持；本机的 symlink 也因 Windows `EPERM` 失败，`doctor` 因此报告 hosts detected / no link。这个结果已保留在实验日志中，没有伪装成已安装。研究结论是：img2threejs 适合程序化三维重建或空间参考，不适合直接把这张水粉画变成廉价 3D 物体。

`img2pixi2d` 的适用范围与本交付一致：它强调 PixiJS 2D 可编辑层、ownership/matte/occlusion、原像素保留、浏览器实际渲染比较与时间可 seek；但它是 OMP host plugin，不是当前 Codex 的本地 skill，而且 `forge crop` 不会凭空恢复被遮挡像素。因此本实现吸收其方法论，使用手工 source-coordinate mattes，并把隐藏区域的 Gaussian continuation 明确标记为 bounded inferred completion。

## Layer ownership

| Runtime owner | Asset | Source region | Motion |
| --- | --- | --- | --- |
| `BG_00_canvas_original` | original PNG | full canvas | comparison/reference mode only |
| `BG_10_school_ground` | `static-underlay.png` | full canvas; only swept owner union softened | still, keeps school/ground quiet |
| `ENV_20_trunk_branches` | Pixi tint aid | source coordinate | still, low alpha |
| `ENV_30_foliage_rear` | left + middle RGBA crops | `[218,34,365,392]`, `[468,272,380,382]` | independent harmonic signals |
| `CHAR_40_boy` | full-size source sprite + `boy` matte | `[880,54,300,530]` | deliberately still; no invented gesture |
| `ENV_50_foliage_front` | foreground RGBA crop | `[794,0,654,390]` | slower, separate phase/frequency |
| `FX_60_painted_shadow` | shadow crop | `[300,770,900,280]` | very low-alpha drift |

The leaf owners are rendered as Pixi `MeshSimple` quads with their own position, rotation and non-uniform scale. The source-coordinate full-resolution masks are kept in `assets/masks/` and the crop alpha is kept in `assets/layers/`. Mask borders can be toggled in the debug panel.

## Directing the 10 seconds

The motion is a restrained three-part breath rather than a global wave:

1. `0.0–1.4s`: hold the original composition; wind envelope eases in from zero.
2. `1.4–8.1s`: three foliage owners move with different phases and frequencies; the rear leaves are slightly more responsive than the high foreground canopy. The boy stays still, so the tension comes from the world moving around him.
3. `8.1–10.0s`: the wind and painted shadow ease back to a still frame; `t=10.0s` returns to the locked composition.

No particles, global displacement, full-image wave, face animation or invented eye/hand acting is used.

## Controls and export

```powershell
npm install
npm run assets
npm run dev
```

Open `http://127.0.0.1:5173/` (or the port Vite reports). The panel provides Play/Pause/Reset, a seconds scrubber, intensity, original/separated comparison, layer isolation and mask borders. `renderAtTime(seconds)` is deterministic and shared by UI scrubbing, browser evidence and frame export. The `Export 10s WebM` button records a silent 24 fps browser video from the same canvas; PNG export remains the preferred source-of-truth for frame-accurate editorial encoding.

```powershell
npm run capture:evidence
npm run export:frames -- --start=0 --end=240
```

The five required browser captures are written to `edits/evidence/`; the full 24 fps sequence is written to `edits/exports/SH03/frames/`. The PNG button in the UI exports the current frame; the WebM button records the complete ten-second shot. If an editorial H.264 is required, encode the deterministic PNG sequence in a workstation with FFmpeg.
