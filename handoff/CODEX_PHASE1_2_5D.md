## 创作命题

一名男孩坐在台湾旧校舍旁的大树上，享受无人发现他的游戏。现在只制作 **SH03 躲藏的幸福** 的 8–12 秒动画镜头，不要抢先做完整 90 秒，也不要让镜头从第一秒就诡异。

要让画面**真的活着，却几乎感觉不到它在动**：有组织的树叶簇随着风发生差异化的轻微摆动；树影以非常低的幅度移动；男孩可能眨眼、调整视线或晃动一根手指（只在分离素材与遮挡真实允许时），建筑、树干基本稳定。结尾安静得有些过分。这个“过分的安静”比夸张的超现实滤镜更 creepy。

原画是完整的水粉 / 手绘质感。**首要 KPI 是保住它的纸张纹理、颜色关系、构图与角色身份，而不是炫技。**

2. 可按官方指引安装/检查 `img2threejs`（确认可信来源，检查命令与现有环境）：
   ```powershell
   npx --yes img2threejs@latest install
   npx --yes img2threejs@latest doctor
   ```
   安装后需要重启 Codex 才能发现新 skill。这仅是**可选 3D 研究工具**，不强制把整幅插画重建为几何体。安装失败如实记录。
3. 研究 `https://github.com/img2threejs/pixi2d` 中层级、遮挡、分离对象与质量门槛的做法；它目前主要是 OMP plugin，**不得假装已在 Codex 中以可运行 skill 安装**。无需安装它也可以直接用 PixiJS API 实现。
4. 你拥有技术选型自由，但请先判断基于原画的 `PixiJS v8 + TypeScript` 是否是最少破坏原画的方案；Three.js 只在真实 3D 纵深 / 镜头失去身体的段落必要时引入。

## 执行流程（不是只写计划）

**Phase 0 · 原图校验**：明确 source image 路径、尺寸 1448×1086、SHA256 `5bdda3d0d314a20af09df6ef1480ccc888a002ee5a3054228e88857c2c9730f4`。不能对原图直接进行有损覆盖。若用户只提供一张扁平 PNG，如实说明拆分与被遮挡像素不可凭空得知。

**Phase 1 · 场景拆层**：分离学校与地面、静止树干、后层叶簇、男孩、遮挡他的前层叶簇、可动光影。使用遮罩 / 人工校准 / 合理的局部补绘。保留 mask 源数据与资产 manifest；未经授权不凭空创造大面积隐藏物。需要手工完善的区域要留下清晰标记。绝对不能仅使用整图做全局缩放，再宣称已实现独立图层。

**Phase 2 · 真正的镜头**：制作可运行 10 秒 2.5D 动画，而不是三维展台。叶片群不同频、相位、幅度；风有长短变化，不允许所有叶片同步正弦摇摆。男孩只做少量真实可控的表演。保持树干与建筑绝对稳定，防止边缘撕裂。不要自行增添花瓣、漂浮灰尘、粒子雨、复杂镜头转场和好看的 UI。

**Phase 3 · 工程可控**：在开发路由提供 play / pause / scrub、motion intensity、mask/layer toggle、source A/B、reset；画面本身无 UI。API 需要 `renderAtTime(t)`（严格与帧率无关，时间可跳转），提供导出 24fps 无声帧序列/视频的命令，说明如何后期铺授权音乐。

**Phase 4 · 真实检查**：启动 Vite、在浏览器中查看完整 10 秒；导出至少 t=0 / t=2.5 / t=5 / t=7.5 / t=10 的真实画面截图，附原画对照。检查男孩脸和鞋是否变形、叶缘是否撕裂、遮挡缺口是否出现、树影是否错位、纹理是否塑料化。做至少一次基于截图的修复，再检查。运行 build / typecheck / basic test，记录结果与尚存缺陷。

**Phase 5 · 交付 GitHub**：实际 commit + push 源码、清晰目录、可复用图层/遮罩、运行方式、截图证据、实验日志、缺陷清单到 `peekaboo` 仓库（不得强推、不得覆盖历史研究）。如无法推送，提供 patch 或完整改动包及具体原因。提交不得包含未经授权的 Swallow 音乐音源。

## 美学负面清单

- 禁止把水粉画转为廉价低模 3D、塑料人物、Unity 演示场景。
- 禁止整个画面统一波浪形变或每个物体不停“呼吸”。
- 禁止廉价梦核滤镜、大眼、无限走廊、过度颗粒、眩光、彩色 HUD、随机粒子。
- 禁止只生成漂亮截图，不保留可修改的图层与 timeline。
- 不要用不受控的模型生成替代图像中本来就存在的角色和背景。
- 禁止为了表现“动画”而牺牲静止画面的完整性。

## 交付清单与成功定义

1. 本地可运行页面 + source image + 编辑过的图层资产；
2. 同一个镜头的确定性播放、暂停、拖动与帧导出；
3. t=0 / 2.5 / 5 / 7.5 / 10 的截图与原图对比；
4. 说明每一层做了什么动画、具体幅度、如何修改；
5. 手绘原画保真评估、遮挡风险与待改清单；
6. GitHub 提交、启动命令与技术决定记录。

**第一版宁可 10 秒极其精细，也不要 90 秒充满会动的 AI 图。**

结束时请给一份像专业 Creative Coding 制片交付那样的简短汇报：实现内容、已验证证据、你的审美判断、未解决的问题、下一轮只改什么。请独立作出工程细节决策，不要停在提问或方案。
